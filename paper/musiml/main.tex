\title{Checking Quran Recitation from Noisy ASR Transcripts: a Two-Task Competition on Real Learner Data}

\author{Anonymous Author(s)}

\begin{document}
\maketitle

\begin{abstract}
We propose a competition on the checking problem behind every Quran-memorization app: given a noisy ASR transcript of a learner reciting from memory, decide \emph{which} ayahs were recited, \emph{where} each begins and ends, and \emph{whether} the learner should be corrected---without flagging the breath repeats, restarts and stutters that make up most real recitation. We release 258 human-reviewed transcripts of production recordings (1{,}267 gold ayah chunks) with two fixed scorecards, an oracle-checked recording-level held-out split, a 10\% review sample, checksums, and three evaluated baselines, including the deployed app's hand-built pipeline.
\end{abstract}

\section{Social impact and task design}
Hundreds of millions of Muslims memorize Quran, normally with a listener who corrects them. Apps that supplement that listener transcribe the recitation with commercial ASR and must then solve a \emph{checking} problem on noisy text: isti'adhah and basmala, ASR errors, breath-catching repeats, full restarts, stutters, self-corrections, skipped words, abandoned ayahs. A plain word-error diff calls all of that a mistake. In our production data 87\% of ayah chunks are clean, and over-flagging benign behaviour destroys a learner's trust faster than missing an occasional error. Public Quran speech resources target ASR of professional read recitation; to our knowledge none labels the learner-facing checking task on real memorization attempts.

\begin{itemize}
\item \textbf{\taskA\ --- detect + split.} Input: one raw transcript. Output: the set of ayah ids recited and a segmentation of the words by ayah, or \emph{abstain} for non-Quranic input. Frozen (v1.1).
\item \textbf{\taskB\ --- within-ayah mistake events.} Input: the transcript words of \emph{one} ayah (a gold \taskA\ chunk), the reference ayah text, and the chunk's position in the recording. Output: a list of events, each typed (restart\_repeat, full\_repeat, stutter, self\_correction, substitution, omission, insertion, word\_order, truncation, asr\_garble) with a verdict \emph{benign} / \emph{corrected} / \emph{mistake} / \emph{uncertain}---the last because text alone cannot always separate ASR error from recitation error. Released as a labeled pilot; full labels ship before launch (\S\ref{sec:plan}).
\end{itemize}

\section{Dataset}
\label{sec:data}
\textbf{Source and consent.} 258 recordings by adult users of a Quran-memorization chat bot, under terms of service that disclose review for service improvement; commercial ASR; every row human-reviewed (ayah assignment, split, confidence) after LLM pre-labeling. 254 rows are Quranic (604 distinct ayahs from 45 surahs; 1--46 ayahs and 2--261 words per recording, median 40), 4 are non-Quranic negatives. Text only; learner and recording identifiers replaced by surrogate ids; negatives hand-checked for personal content. The Quran is a closed public canon, so transcripts carry essentially no personal information.

\textbf{Split.} Deterministic stratified 60/40 by \emph{recording} (151/107 rows; 711/556 chunks), never by chunk, so one reciter's ASR quirks cannot leak; negatives 2/2; known-ambiguous rows pinned to train so the held-out oracle floor is exactly~0. \taskB\ shares the split and id space.

\textbf{\taskB\ labels.} Frozen schema: verbatim hypothesis/reference words, script-derived token spans, verdict, note. Reproducibility rules: word-final letter drops are \emph{uncertain}; a truncated \emph{last} ayah of a recording is benign (the learner stopped recording), elsewhere a mistake; a slip inside an abandoned first attempt is swallowed by the repeat. The pilot covers 99 chunks of 20 recordings (86 clean; 17 events: 11 substitutions, 3 omissions, 2 truncations, 1 full repeat), LLM-proposed and marked \texttt{human-pending} until sign-off. A naive diff flags only 21\% of all 1{,}267 chunks; the rest match the reference exactly after canonicalization, so completing the labels is a review of $\approx$270 chunks.

\section{Metrics and baselines}
Fixed scripts; lower is better; components in $[0,1]$, always reported next to the scalar.
\taskA: $\texttt{research\_score} = \text{detection err} + \text{split err} + \text{abstention err}$ (exact ayah-set match; word-assignment accuracy after metric-only orthographic canonicalization; abstention on negatives).
\taskB: $\texttt{study3\_score} = 2\cdot\text{miss} + \text{false\_alarm} + \text{benign} + \text{clean}$. A prediction matches a gold event if their token spans overlap. \emph{miss}: gold mistakes not flagged (an \emph{uncertain} prediction on one costs a half); \emph{false\_alarm}: flags touching no gold mistake/uncertain event, over all flags; \emph{benign}: gold benign/corrected events flagged as mistakes; \emph{clean}: clean chunks with any flag---the product's false-flag rate, its own term because clean is the majority class. Adjacent same-type predictions are merged, so word- and phrase-level detectors score alike; type agreement and uncertain-rate are reported, not summed. Both scores: empty system 2.0, gold 0.

The \taskB\ pilot is small by design: it fixes schema and metric and already separates the failure modes that matter.

\section{Competition plan, feasibility and ethics}
\label{sec:plan}
\textbf{Phases.} (1) Launch with \taskA\ frozen and \taskB\ fully human-reviewed on the 258 recordings ($\approx$270-chunk review; tooling exists). (2) Public leaderboard on the released test split. (3) Final ranking on a \emph{hidden} test set of new recordings drawn from $>$20k further production recordings of the same app, labeled with the same protocol, user-reported false flags over-sampled as adversarial gold; released afterwards. A submission is one Python file per contract; scoring takes under a second, so an \emph{agent track} (autonomous loops, logged per experiment) runs beside the human track under identical rules.

\textbf{Feasibility.} Harness, data, checksums and the 10\% sample (26 recordings, both tasks) are attached; baselines run offline. \textbf{Ethics.} Text only, de-identified, adult users, ToS-disclosed review, CC~BY~4.0; the task is corrective feedback, not surveillance, and \emph{uncertain} is a first-class output so systems are not pushed to over-claim. \textbf{Participation.} Pure text, tiny data, sub-second evaluation, a task every Quran-learning app faces; Arabic NLP, speech and coding-agent groups are natural entrants.
